# iaedu-bridge

OpenAI-compatible bridge for the [IAedu](https://chat.iaedu.pt) chatbot API (GPT-4o, GPT-5.x):
`/v1/models` and `/v1/chat/completions` with streaming, token usage estimates, stable IAedu threads,
emulated tool calls (agents such as Goose can run shell, MCP and skills through it) and retry/backoff
for IAedu's rate limits. One bridge per person, locked to one IAedu API key.

## Install (Linux, macOS, Windows)

```
uv tool install git+https://github.com/mariolpantunes/iaedu-bridge   # or, from a clone: uv tool install .
iaedu-bridge configure          # asks for the endpoint, channel id and API key (hidden input)
iaedu-bridge check              # shows what is configured (never prints the key)
iaedu-bridge serve              # http://127.0.0.1:8000/v1
```

Needs Python 3.11 or newer (uv fetches it). Upgrade with `uv tool upgrade iaedu-bridge`.

The three values come from IAedu: Explore Agents, open the agent (for example "OpenAI GPT-4o"),
Agent Menu, API Info. Only agents that show API Info can be used; custom agents cannot.

Settings are read from the environment, then `./.env`, then the per-user file written by `configure`
(`%APPDATA%\iaedu-bridge\config.env` on Windows, `~/.config/iaedu-bridge/config.env` elsewhere, mode 600).

| Variable | Meaning | Default |
|---|---|---|
| `IAEDU_ENDPOINT`, `IAEDU_API_KEY`, `IAEDU_CHANNEL_ID` | required, from API Info | |
| `BRIDGE_API_KEY` | bearer token clients must send (generated by `configure`) | none |
| `IAEDU_MODEL` | model id reported by `/v1/models` | `iaedu-5.5` |
| `IAEDU_RETRIES`, `IAEDU_BACKOFF` | retries on 429/5xx/timeouts, first delay in s (doubles) | 3, 2 |
| `IAEDU_MAX_CONCURRENCY`, `IAEDU_TIMEOUT` | parallel IAedu requests, seconds | 2, 180 |

Client: `OpenAI(base_url="http://127.0.0.1:8000/v1", api_key=<BRIDGE_API_KEY>)`.
Use a model id without `gpt-5` in it (the default `iaedu-5.5` is fine): some clients route `gpt-5*`
names to `/v1/responses`, which the bridge does not serve. The requested model name is ignored; the
agent behind the endpoint decides.

## Goose

```
iaedu-bridge goose-provider --install   # writes custom_iaedu.json into Goose's custom_providers folder
iaedu-bridge goose run -t "your prompt" # starts the bridge in-process and runs goose on it
iaedu-bridge goose -- session           # arguments after -- go to goose
```

On Windows the provider file goes to `%APPDATA%\Block\goose\config\custom_providers` (unverified:
use `--dir` if your Goose keeps it elsewhere; `goose-provider` without `--install` prints the JSON).

## What works and what does not

- IAedu ignores client-side tool definitions and its agent refuses prompts that claim it can call tools.
  The bridge therefore frames tools as a JSON-formatting task for a separate executor and converts the
  reply to `tool_calls` (`src/iaedu_bridge/tools.py`). It worked with Goose's developer extension, but it
  is prompt-based: expect occasional plain-text answers instead of a call.
- With `tools`, streaming is buffered (the reply is parsed as JSON before anything is sent).
- IAedu has a per-user daily limit; when it is hit the bridge answers HTTP 429 with IAedu's message.
- Token counts are tiktoken estimates (`o200k_base`), not IAedu numbers.

## Development

```
python -m venv venv && venv/bin/pip install -e . --group test     # Windows: venv\Scripts\python
PYTHONPATH=src venv/bin/python -m unittest discover -s tests         # 52 tests, ~5 s, no network
```

- `tests/fake_iaedu.py`: in-process IAedu fake with fault injection (429s, 5xx, timeouts, empty, garbled and
  truncated streams, thread memory); sweeps in `tests/test_sweep_*.py` (sizes up to 400k chars, unicode,
  fuzzing, bursts, long agent loops). Soak: `SWEEP_SEED=7 SWEEP_N=5000 ... -k test_random_bodies`.
- Live, opt-in and quota-aware: `uv run scripts/live_sweep.py --budget 25 --pace 4` (bridge running), and
  `scripts/live_recipes.sh` (Linux/macOS, Goose recipes in `recipes/` that generate and compile Rust).
- Lint and types as in CI: `ruff check src`, `ruff format --check src`, `basedpyright`, `vulture`.
